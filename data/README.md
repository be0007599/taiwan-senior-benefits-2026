# 福利資料目錄

本目錄保存網站可以讀取、且可由版本控制追蹤異動的福利資料。

## 檔案

- `benefit.schema.json`：單筆福利資料的 JSON Schema。
- `benefits.central.json`：第一輪已核驗的 28 項中央／全國性福利種子資料。
- `benefits.local.json`：22 筆縣市敬老卡／社福卡，以及健保署115年7月14日清單確認的18筆地方老人健保補助；未取得115年完整主管機關說明者保留待確認狀態。
- `benefits.local.chongyang.json`：13筆已取得115年公告或現行法規支持的縣市敬老／重陽禮金正式方案。
- `benefits.local.health-check.json`：7筆已由地方衛生主管機關或中央政府115年地方服務索引核實的長者加值健檢方案。
- `benefits.dental.json`：23筆已核驗假牙方案，分開記錄一般長者、經濟弱勢、原住民族與榮民資格體系。
- `benefits.assistive.json`：身心障礙者輔具費用補助；長照輔具額度則記在中央長照3.0方案。
- `benefits.local.health-aids.json`：5筆地方老花眼鏡、視力檢查及低收入長者助聽器補助。
- `benefits.local.support.json`：54筆地方住院看護、送餐、獨居關懷與緊急救援服務；官方金額衝突者保留衝突狀態。
- `benefits.local.transport.json`：20筆已核驗地方長照交通接送方案；與敬老卡、復康巴士及社區式日照交通分開記錄。
- `benefits.local.rehab-bus.json`：20筆已核驗復康巴士正式方案；核心資格通常為身心障礙證明、輪椅需求或地方專案核准，僅少數地區把經評估失能的65歲長者直接列為資格。
- `jurisdiction-coverage.json`：22 縣市第一輪查核覆蓋摘要；此檔不是完整地方福利清單。
- `chongyang-coverage.json`：22 縣市115年重陽禮金專項核驗矩陣；`pending_confirmation` 與 `conflicting_sources` 不得當成已可領取方案。
- `denture-coverage.json`：22縣市115年假牙專項覆蓋矩陣；18縣市已有正式方案，4縣市保留待主管機關確認狀態。
- `inpatient-caregiver-coverage.json`：22縣市弱勢長者住院看護補助矩陣；14縣市已確認、2縣市官方額度衝突、6縣市待主管機關確認。
- `meal-delivery-coverage.json`：22縣市送餐專項矩陣；22縣市均已取得115年或現行政府依據。嘉義縣只確認服務存在，詳細餐次與費用仍須1966評估。
- `emergency-system-coverage.json`：22縣市緊急救援系統矩陣；22縣市皆已取得115年或現行地方主管機關依據，但部分縣市仍須確認裝機量能與個案費用。
- `transport-coverage.json`：22縣市長照交通接送矩陣；目前20縣市已有正式方案，嘉義縣與連江縣仍待取得足以證明115年現行內容的地方原頁。
- `rehab-bus-coverage.json`：22縣市復康巴士覆蓋矩陣；目前20縣市已核驗，其餘嘉義縣及連江2縣市仍缺足以支持115年完整資格與費率的主管機關資料。

## 重要界線

`benefits.central.json` 採「一筆資料代表一項方案」。

`benefits.local.json` 完成兩個地方福利批次：22 縣市敬老卡，以及18筆地方老人健保費補助。其他檔案再按重陽禮金、健檢、假牙、健康輔具與生活支持分批保存。任何覆蓋摘要都不能當成完整方案資料。

截至115年8月18日，正式資料共211筆。這個數字代表「已建立的方案紀錄」，不是宣稱全台所有鄉鎮市區加碼已蒐集完畢；同一縣市可能有多個資格互斥的方案。

## 驗證

在專案根目錄執行：

```powershell
npm run validate:data
```

驗證項目包括：

- 中央種子資料是否為 28 筆。
- 地方敬老卡是否為 22 筆且每縣市恰有一筆。
- 地方老人健保補助是否為18筆；未列地方加碼的縣市不以空白紀錄冒充福利。
- 各批次筆數是否符合目前核驗基線：重陽13、地方加值健檢7、假牙23、身障輔具1、地方眼鏡與助聽器5、地方生活支持／住院看護／送餐／緊急救援54、地方長照交通20、地方復康巴士20。
- 22 縣市是否完整且沒有重複。
- 假牙覆蓋矩陣中的正式方案ID是否存在、是否屬於同一縣市，以及待確認縣市是否未混入正式方案。
- 住院看護矩陣是否完整22縣市；已確認及官方衝突狀態是否有正式方案，待確認狀態是否保持空白。
- 送餐及緊急救援兩個矩陣是否各自完整22縣市、方案ID與轄區一致，且待確認縣市未被誤連到正式方案。
- 長照交通接送矩陣是否完整22縣市、方案ID與轄區一致，且待確認縣市未混入正式方案。
- 復康巴士矩陣是否完整22縣市、方案ID與轄區一致，且待確認縣市未混入正式方案。
- `program_id` 是否唯一且格式正確。
- 中央與地方合併後的 `program_id` 是否仍全域唯一。
- 必填欄位、資料狀態及日期格式是否正確。
- 每筆資料是否至少有一個官方來源。
- 官方網址是否來自政府機關或列入白名單的官方公共服務網域。
- 已核驗資料是否有最後查核日期。
- 若方案有 `availability`，是否使用允許的名額／經費／候補／關閉／未知狀態，以及非持續受理方案是否強制標示 `check_required: true`。
- 官方來源類型是否符合資料字典，避免新增資料只通過網址檢查卻無法由前台正確標示來源性質。

## 編輯規則

1. 不直接覆蓋歷史事實；方案金額或資格變動時，應更新生效期間並在開發紀錄留下原因。
2. `verified` 只適用於已由主管機關確認目前生效的內容。
3. 「預計、規劃、草案、預算審議中」使用 `planned`。
4. 官方資料互相矛盾且尚未排除時使用 `conflicting_sources`。
5. 尚缺當年度金額或條件時使用 `pending_confirmation`。
6. 搜尋引擎摘要、媒體及民間整理網址不得寫入 `official_sources`。
7. `validity` 只表示制度或年度有效期間；名額、經費及設備量能另以 `availability` 表示。非 `continuous` 狀態必須設 `check_required: true`。
